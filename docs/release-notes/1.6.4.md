# Glacier 1.6.4

这一版只修体验细节，冻结后端、数据格式和外部 API 都没动，可以直接覆盖升级。

## 冻结状态不再「稍等一会儿」才显示

之前冷启动进主页：应用图标第一时间出来了，但冻结应用还要再等一会儿才转成冻结样式
（灰度图标 + 次要色名称）。原因是首帧快照里冻结态是写死的 `false`，真实冻结态只由
「枚举全部应用」的后台刷新补；模拟器 252 个包要 ~0.6 秒，真机包更多、`PackageManager`
更慢，这段窗口里每一帧都还是「未冻结」。

现在：

- 首帧预热时直接用刚读到的 `ApplicationInfo` 算冻结态（冻结标志本来就在这份对象上，
  不再额外查 `PackageManager`，也不经过后端）；
- 「主页」与「全部应用」拆成两段刷新：主页那十几个包毫秒级先到位
  （实测 1~2ms），全量枚举随后补应用页；
- 全量刷新复用枚举到的 `ApplicationInfo`，252 个包实测 593ms → 480ms。

效果：冷启动首帧、以及每次刷新/冻解冻之后，主页的冻结样式都是立刻正确的。

## 预测性返回动画开关不再「闪一下」

开关「主题设置 → 预测性返回动画」时，重建出来的新窗口第一帧常常还没拿到系统栏
`WindowInsets`，整页会先按「没有状态栏」排一帧、下一帧再跳回正确位置 —— 真机录屏里就是
一次 1 帧、整页上移一个状态栏高度的闪烁（实测恒为 144px）。冷启动这一帧被启动画面盖住，
重建没有启动画面所以看得见。

现在重建时内容照常组合（返回栈、页面状态照原位恢复），但首帧先不显示，等系统栏 inset
真正下发后再亮出来；底色与窗口背景同色，视觉上就是同一个空页面。开关本身仍沿用官方
MIUIX example 的「改进程标志 + 重建」方式，「关闭后保留返回动画、只是不再预览」的语义不变。

## 设置里依赖上一项的行，动画对齐 MIUIX OS4

「隐藏应用名称」打开后，「主页标签字号」这一行会收起；「自动冻结」关闭后，它下面的整组
设置会收起。这些 dependent-option 行之前只做了淡入淡出、没有高度过渡，行是「淡一下然后
硬跳」。现在按 MIUIX 官方范式补上 `fadeIn() + expandVertically()` /
`fadeOut() + shrinkVertically()`，行高和透明度一起过渡。

## 安装

- 要求 Android 13（API 33）及以上
- `adb install Glacier-release.apk`，或直接在设备上打开
- 包名 `com.ayang.glacier`；与此前版本同签名，可直接覆盖升级
- SHA-256 见附件 `SHA256SUMS.txt`

## 已知限制

- 长按菜单标题 + 分割线后超过 6 行会在弹层内滚动（上游 `POPUP_PROBE_COUNT = 8`）。
- 锚点浮层依赖硬件 `RenderEffect`，软渲染环境（SwiftShader）不可用；玻璃光学表现仍需真机确认。
- 预测性返回开关的「首帧不闪」修复在模拟器上无法复现（模拟器首帧 inset 已就绪），
  建议真机确认；若个别机型仍有 1 帧同色空白，把 `RecreatedInsetsGate` 的兜底帧数放宽即可。
- 预测性返回开关在 OEM 手势导航上的实际观感建议真机确认（模拟器是 AOSP 手势）。
- 应用页的「全部应用」列表仍由启动刷新填充；通常切过去时已就绪。
- 冻结真正生效依赖你选的工作模式，`default` 模式只记状态。
